# 本地构建与跑通 M0

## 0. 先说结论（跑通标准）
M0 已经能 **零资源运行**：即使 `assets/` 里没有任何图片，窗口也会弹出来显示深空蓝纯色。
所以「跑通」的判定是：**窗口能弹、能关、控制台无报错**。先把这套确认了，再往里塞 Kenney 贴图。

> ⚠️ **千万别双击 `build.bat`**。双击启动的是普通 `cmd.exe`，它**不加载 Git Bash 的 PATH**，
> 加上原脚本报错即退，窗口会「闪一下就没」——你根本看不到错在哪。
> 正确做法：开 **Git Bash**（或 Developer Command Prompt），`cd` 到项目目录，设好 `SFML_DIR`，
> 再 `./build.bat`。新版 `build.bat` 已在报错时 `pause` 卡住窗口，但**还是从终端跑**最稳妥。

---

## 1. 关键前提：SFML 版本钉死 2.6.x ⚠️

**不要用 SFML 3.x。** SFML 3 改了大量 API（`sf::VideoMode` 的构造方式、`sf::Event` 的轮询写法都变了），
这份 M0 代码按 2.5/2.6 写的，碰上 3.x 会在 CMake 配置或编译阶段直接挂。

- 下载地址：https://www.sfml-dev.org/download/sfml/2.6.2/
  - 选 **GCC / MinGW** 版 或 **Visual C++ 2017–2022** 版，取决于你下面选哪条工具链。
- 或用 vcpkg 装 2.6 线：`vcpkg install sfml:x64-windows`（默认就是 2.6）。

---

## 2. 两条路，选你顺手的

> 你已有 **Visual Studio 2022 Professional**，直接用路线 A 即可，不需要 MinGW / `g++`。

### 路线 A（推荐，你有 VS）：官方预编译 SFML（MSVC 版）+ VS「打开文件夹」
`CMakeLists.txt` 已做两件事，让这路线几乎零手动配置：
- **自动探测 SFML**：只要把 SFML 解压到 `C:\SFML-2.6.2`（或其他几个常见路径），VS 配置时自动找到，不用手填 `SFML_DIR`。
- **自动拷贝 DLL**：构建后自动把 `sfml-*-2.dll` 拷到 exe 同目录，不用手动拷。

步骤：
1. 下 SFML 2.6.2 的 **Visual C++ 2017–2022（64-bit）** 预编译包：
   https://www.sfml-dev.org/download/sfml/2.6.2/ （⚠️ 别下 GCC/MinGW 版）
2. 解压到 **`C:\SFML-2.6.2`**（务必让路径里出现 `C:\SFML-2.6.2\lib\cmake\SFML\SFMLConfig.cmake`）。
3. VS2022 → 「打开本地文件夹」→ 选 `D:\Code\C_workspace\game\planewar`。VS 识别 CMake，自动配置。
4. 配置选 `x64-Debug`，按 **Ctrl+F5**（不调试运行）。窗口应弹出。
   - 若 VS 配置时报 `Could NOT find SFML`：说明自动探测没命中（路径不是上面那几个），
     在 VS「项目 → CMake 设置 → CMake 变量和缓存」里手动加 `SFML_DIR = C:/你的路径/lib/cmake/SFML`。

### 路线 B（备选，更省心但首次慢）：vcpkg
1. `git clone https://github.com/microsoft/vcpkg` + 跑 `bootstrap-vcpkg.bat`。
2. `.\vcpkg\vcpkg install sfml:x64-windows`（首次会从源码构建依赖，等几分钟）。
3. VS 的 CMake 设置里把「CMake 工具链文件」指向 `C:\vcpkg\scripts\buildsystems\vcpkg.cmake`。
4. 在 `CMakeLists.txt` 顶部加一行 `set(VCPKG_APPLOCAL_DEPS ON)`（同时把下面那段「自动拷贝 DLL」删掉，避免重复）。vcpkg 会自动拷 DLL。

### 路线 C：MinGW-w64 + Git Bash（仅当你坚持不用 VS 时）
1. 装 MinGW-w64（GCC 11+ 最佳），确认 `g++.exe` 在 PATH。
2. 下 SFML 2.6.2 的 **GCC / MinGW** 预编译包，解压到比如 `C:\SFML-2.6.2`。
   - ⚠️ 官方 MinGW 包是用特定 GCC 版本编的，**你的 MinGW GCC 大版本要尽量接近**，差太多会链接/运行崩。
3. Git Bash 里设 `SFML_DIR` 后构建（或直接 `./build.bat`）：
   ```bash
   export SFML_DIR="C:/SFML-2.6.2/lib/cmake/SFML"
   cmake -G "MinGW Makefiles" -S . -B build
   cmake --build build --config Release
   ```
4. 把 `C:\SFML-2.6.2\bin\*.dll` 拷到 `build\PlaneWar.exe` 同目录运行。

## 3. 跑通后你该看到什么
- 一个 **800×600、深空蓝** 的窗口，标题 `PlaneWar`。
- 按右上角 × 能正常关闭；若没放背景图，控制台会打印：
  ```
  [M0] 未找到 assets/background.png，使用纯色清屏兜底。 把 Kenney 资源放进去后即可显示。
  ```
- 窗口持续响应关闭事件、不卡死（说明固定步长主循环在转）。

---

## 4. 放一张背景图验证资源链路（可选但强烈建议）
把任意一张图命名为 `background.png` 丢进 `assets/`，重新编译运行——窗口应该铺满这张图。
这证明 `AssetManager.LoadTexture → Renderer.DrawSprite(SpriteId::Background)` 整条链路通了。
Kenney 正式素材留到 M1 再接。

## 5. 常见坑速查表

| 现象 | 原因 | 解决 |
|---|---|---|
| CMake 配置报 `Could NOT find SFML` | 没设 `SFML_DIR` 且自动探测未命中 | 解压到 `C:\SFML-2.6.2` 让自动探测命中；或在 VS「CMake 设置→缓存」手动加 `SFML_DIR = .../lib/cmake/SFML` |
| 运行 exe 弹「找不到 sfml-graphics-2.dll」 | 动态链接 DLL 没拷 | 路线 A 已自动拷贝（构建后看输出目录有无 sfml-*-2.dll）；若仍缺，手动把 SFML `bin/*.dll` 拷到 exe 旁 |
| 编译报 `sf::VideoMode` / `sf::Event` 相关错 | 装了 SFML 3.x | 卸了换 2.6.2 |
| MinGW 链接一堆 `undefined reference` | MinGW 版本与 SFML 预编译包不匹配 | 改用 vcpkg 的 mingw 端口，或换匹配 GCC 版本 |
| MSVC 报 `LNK2038` / 运行时库不匹配 | SFML 静态/动态与你项目设置不一致 | 统一用动态（默认）或统一静态，别混 |
